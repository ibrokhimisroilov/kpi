# Бот 24/7 бесплатно: Render + Supabase

Бот работает в интернете круглосуточно: **бесплатно, без банковской карты, без продлений**.
От вас — 4 коротких шага (около 30–40 минут, один раз). Всё остальное делает разработчик.
Для сотрудников ничего не меняется: бот тот же, ссылка та же.

## Как это устроено

```
  Сотрудники и руководители ⇄ Telegram ⇄ Render (здесь работает бот) ⇄ Supabase (здесь хранятся данные)
```

- **Render** — бесплатный хостинг, на нём работает бот. Код бот получает из **GitHub**.
- **Supabase** — бесплатная база данных: задачи, оценки, сотрудники.
- Бесплатный Render усыпляет сервер после 15 минут тишины, поэтому **бот сам «будит» себя каждые
  10 минут** и **каждые 5 минут сам проверяет**, кому пора напомнить. Никаких внешних «будильников»
  заводить не нужно.
- Каждый вечер в **23:00** руководителям приходит файл с резервной копией базы (как и раньше).

**Что делает разработчик:** готовит файл `deploy\render.env` с настройками бота (токен, ID руководителей,
ключ Gemini), создаёт в вашем GitHub закрытое хранилище `kpi-bot` и загружает туда код, переносит
накопленные задачи и сотрудников в облачную базу и выключает бота на компьютере.

> **[может отличаться]** — так помечены названия кнопок: сайты иногда меняют надписи. Если надпись
> немного другая, ищите кнопку с похожим смыслом.
>
> **Если где-то просят банковскую карту — ничего не вводите и напишите разработчику.**

## Шаг 1. GitHub — 5 минут

1. Откройте <https://github.com/signup> и нажмите **Continue with Google** **[может отличаться]**
   (или зарегистрируйтесь по почте). Имя пользователя — любое, латиницей.
2. Отправьте разработчику своё **имя пользователя** GitHub. Пароль не нужен — не отправляйте его.
3. **Один раз**, когда разработчик будет загружать код, на компьютере откроется окно
   **Connect to GitHub** или страница GitHub в браузере. Нажмите **Sign in with your browser**, затем
   **Authorize** (**Authorize git-ecosystem**) **[может отличаться]**. Больше GitHub вас не побеспокоит.

## Шаг 2. Supabase — база данных, 10 минут

1. Откройте <https://supabase.com> → **Start your project** → **Continue with GitHub** → **Authorize**
   **[может отличаться]**.
2. Если попросит создать организацию: имя любое, **Type: Personal**, **Plan: Free ($0)** →
   **Create organization**.
3. **New project** **[может отличаться]**:
   - **Project name**: `kpi-bot`;
   - **Database Password**: нажмите **Generate a password**, затем **скопируйте пароль и сохраните его**
     в надёжном месте (менеджер паролей, заметка, листок в сейфе). Он нужен прямо сейчас и пригодится потом;
   - **Region**: **Central EU (Frankfurt)**;
   - остальное не меняйте → **Create new project**. Подождите 1–2 минуты.
4. Вверху страницы проекта нажмите **Connect** → выберите **Session pooler** → скопируйте строку
   подключения **как есть** — вместе с `[YOUR-PASSWORD]`, ничего в ней не меняйте **[может отличаться]**.
   Строка начинается с `postgresql://postgres.` и содержит `pooler.supabase.com:5432`.
   **Не берите** Direct connection (`db.….supabase.co`) и Transaction pooler (порт `6543`).
5. В папке бота откройте файл `deploy\render.env` Блокнотом (правый щелчок → **Открыть с помощью** →
   **Блокнот**) и замените текст `ВСТАВЬТЕ_СЮДА_…` после знака `=`:
   - в строке `DATABASE_URL=` — на строку из Supabase;
   - в строке `DATABASE_PASSWORD=` — на пароль из пункта 3.

   Пробелов вокруг `=` быть не должно. Получится примерно так (буквы у вас свои):
   ```
   DATABASE_URL=postgresql://postgres.abcdefghijklmnop:[YOUR-PASSWORD]@aws-1-eu-central-1.pooler.supabase.com:5432/postgres
   DATABASE_PASSWORD=Ваш8Пароль
   ```
   Сохраните: **Файл → Сохранить** (Ctrl+S).
6. Напишите разработчику: «база готова». Он перенесёт данные и выключит бота на компьютере, потом
   скажет, что можно делать шаг 3. **Шаг 3 делайте сразу после его ответа, в тот же час:** с начала
   переноса и до статуса **Live** на Render (шаг 4) бот не отвечает — всего около 30–60 минут. Сообщения
   сотрудников за это время не пропадут: бот получит их, когда заработает (Telegram хранит их сутки).

> В `deploy\render.env` — пароли. Не пересылайте этот файл и не выкладывайте его. В GitHub он не попадает.

## Шаг 3. Render — запуск бота, 10 минут

1. Откройте <https://render.com> → **Get Started** → **GitHub** → **Authorize Render** **[может отличаться]**.
   Если Render спросит о вас (для чего сервис и т. п.) — отвечайте как угодно.
2. **+ New** → **Blueprint** **[может отличаться]**.
3. Render попросит доступ к GitHub: **Connect GitHub** → **Only select repositories** → `kpi-bot` →
   **Install** **[может отличаться]**. Затем выберите `kpi-bot` → **Connect**.
4. **Blueprint Name**: `kpi-bot`. Проверьте: сервис **kpi-bot**, тариф **Free**, регион **Frankfurt**.
   Если написано другое (Starter, $7 и т. п.) — остановитесь и напишите разработчику.
5. Render покажет поля `BOT_TOKEN`, `ADMIN_IDS`, `GEMINI_API_KEY`, `DATABASE_URL`, `DATABASE_PASSWORD`.
   Откройте `deploy\render.env` и в каждое поле скопируйте то, что стоит в файле **после `=`** в строке
   с тем же названием. Если Render предлагает **Add from .env** — можно просто вставить весь файл
   **[может отличаться]**.
6. Нажмите **Deploy Blueprint** / **Apply** **[может отличаться]**.

> **Нет пункта Blueprint или он просит карту?** Создайте сервис вручную: **+ New** → **Web Service** →
> `kpi-bot` → **Language: Docker**, **Region: Frankfurt**, **Instance Type: Free**; в **Environment
> Variables** нажмите **Add from .env** и вставьте весь файл `deploy\render.env`; в **Advanced** →
> **Health Check Path** впишите `/health` → **Deploy Web Service** **[может отличаться]**.

## Шаг 4. Проверка — 5–10 минут

1. Откройте сервис **kpi-bot** в Render. Первая сборка идёт 3–10 минут, затем статус станет **Live**
   **[может отличаться]**.
2. Отправьте боту в Telegram `/start` — появится меню руководителя. **Готово!** Остальное разработчик
   проверит сам.

## Дальше делать ничего не нужно

- **Продлевать ничего не нужно**, заходить в Render и Supabase по расписанию — тоже. Сервисы пишут
  на почту, только если что-то не так.
- **Само собой происходит:**
  - бот «будит» себя каждые 10 минут — Render его не усыпляет;
  - каждые 5 минут бот проверяет напоминания и еженедельную сводку (по понедельникам в 9:00);
  - каждый вечер в 23:00 руководителям приходит файл резервной копии (без звука) — не удаляйте эти сообщения;
  - новую версию бота разработчик выкладывает в GitHub — Render сам устанавливает её за 3–10 минут.
    Бот при этом отвечает, недописанные диалоги не теряются.
- **Бот должен работать только в одном месте** — теперь это Render. `run.bat` на компьютере больше не нужен.
  Если запустите его по ошибке — ничего страшного: он увидит, что бот работает в облаке, напишет
  «Бот уже работает в облаке» и остановится. Просто закройте окно.

### Бесплатные лимиты

| Сервис | Бесплатно | Что важно |
|---|---|---|
| Render | 750 часов в месяц на весь аккаунт (workspace) | Это **ровно один** сервис, работающий круглосуточно. **Не создавайте в этом аккаунте Render других бесплатных сервисов**: часы закончатся до конца месяца, и бот остановится до 1-го числа |
| Render | 5 ГБ исходящего трафика в месяц | Боту хватает с большим запасом |
| Supabase | база до 500 МБ | Хватит на годы: сами файлы-подтверждения хранятся в Telegram. Проект «засыпает» после недели без обращений, но бот обращается к базе каждые 5 минут |
| Telegram | файлы до 50 МБ | Если база вырастет больше 45 МБ, бот предупредит — копию сделает разработчик |

### Если Render попросит карту или изменит условия

**Ничего не потеряется.** Данные хранятся в Supabase, отдельно от Render, а каждый вечер руководители
получают резервную копию в Telegram. Ничего не вводите и напишите разработчику: он перенесёт бота
к другому провайдеру (или временно на компьютер) примерно за 15–30 минут. Сотрудникам ничего менять не нужно.

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| Render: **Deploy failed** / **Build failed** (красный) | Откройте **Logs**, сделайте снимок экрана последних строк и отправьте разработчику (паролей там нет). Частая причина — база: взята не та строка (Direct connection вместо Session pooler), остался текст `ВСТАВЬТЕ_СЮДА_…`, пароль скопирован не полностью. Исправить: Render → **kpi-bot** → **Environment** → **Save Changes** **[может отличаться]** |
| Статус долго не становится **Live** | Первая сборка идёт до 10 минут. Дольше 15 минут — **Logs** → снимок экрана → разработчику |
| Бот молчит в Telegram | 1) Откройте адрес сервиса (вверху страницы сервиса в Render, например `https://kpi-bot.onrender.com`) с `/health` на конце — должно быть слово **`ok`**; **502** или **Service Unavailable** — бот запускается, подождите 1–2 минуты. 2) Подождите 5 минут: если бота перехватила копия на другом компьютере, облачный бот сам вернёт себе сообщения. 3) Render → **Manual Deploy** → **Restart service** **[может отличаться]**. Не помогло — **Logs** → разработчику |
| Бот иногда отвечает через 30–60 секунд | Он «проснулся» после перезапуска Render — изредка это нормально. Если так постоянно, разработчик подключит запасной будильник (см. ниже) |
| Письмо от Supabase: проект **paused** (приостановлен) | Supabase → проект `kpi-bot` → **Resume project** **[может отличаться]**, затем в Render → **Manual Deploy** → **Restart service**. Данные при паузе не теряются |
| Письмо от Render: сервис **Suspended**, кончились часы или трафик | Проверьте, что в аккаунте Render нет второго сервиса, и напишите разработчику. Лимиты обновляются 1-го числа |
| Не пришла резервная копия в 23:00 | Обычно она приходит до 23:10. Не пришла до утра — напишите разработчику |
| Напоминания приходят не в то время | Render → **Environment** → `TIMEZONE` должен быть `Asia/Tashkent` |
| Сменили токен бота в @BotFather | Render → **Environment** → `BOT_TOKEN` → новый токен → **Save Changes** |

## Для разработчика

**1. Файл настроек для Render** (значения секретов на экран не выводятся; `deploy/render.env` внесён
в `.gitignore`, папка `deploy` не попадает в образ):

```
.venv\Scripts\python deploy\make_render_env.py
.venv\Scripts\python deploy\make_render_env.py --database-url - --database-password -   # спросит скрыто
```

Берёт `BOT_TOKEN`, `ADMIN_IDS`, `GEMINI_API_KEY` из `.env`, добавляет `RUN_MODE=webhook`; `DATABASE_URL` /
`DATABASE_PASSWORD` — из параметров или заглушки `ВСТАВЬТЕ_СЮДА_…` (владелец заменит на шаге 2). Повторный
запуск сохраняет уже вписанные `DATABASE_*`. Прочие настройки из `.env` не переносятся — скрипт перечислит
их названия. Строку Supabase можно оставить с `[YOUR-PASSWORD]`: бот подставит `DATABASE_PASSWORD` сам
(спецсимволы экранировать не нужно; пароль, уже вписанный в строку, важнее).

**2. Хранилище и загрузка кода.** Создать закрытое хранилище в аккаунте владельца: в его браузере
<https://github.com/new> → `kpi-bot`, **Private**, без README / .gitignore / license (или
`gh auth login --web` + `gh repo create kpi-bot --private`). Затем из папки проекта:

```
git init
git config user.name "KPI bot"                     # если git ещё не знает имя и почту
git config user.email "<логин>@users.noreply.github.com"
git add .
git status                                         # нет .env, data/, dist/, deploy/render.env
git commit -m "KPI bot"
git branch -M main
git remote add origin https://github.com/<логин>/kpi-bot.git
git push -u origin main                            # Git Credential Manager → браузер → владелец: Authorize
git ls-files .env data dist deploy/render.env      # вывод должен быть пустым
```

Дальше обновления — `git push`; Render разворачивает их сам (zero-downtime: ~60–90 с работают два
экземпляра, задания и напоминания не дублируются — SPEC.md §10.6).

**3. Перенос данных** — до шага 3, при **остановленном** боте на ПК (закрыть `run.bat`, убрать ярлык из
`shell:startup`). Источник — `data\bot.db` или последний файл копии `kpi_backup_ГГГГ-ММ-ДД.db` из Telegram.
Переменные окружения важнее `.env`, поэтому локальный `.env` менять не нужно (PowerShell):

```
Get-Content deploy\render.env | ForEach-Object { if ($_ -match '^(DATABASE_URL|DATABASE_PASSWORD)=(.+)$') { [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process') } }
.venv\Scripts\python -m bot.tools.restore data\bot.db
Remove-Item Env:DATABASE_URL, Env:DATABASE_PASSWORD
```

Одна транзакция, `id` сохраняются, последовательности сдвигаются; в базу, где уже есть сотрудники, —
только с `--force`. Тем же способом облачная база восстанавливается из ежедневной копии.

**4. Проверка и журнал.** Render → **kpi-bot** → **Logs**: при старте — `Бот @… подключён к Telegram`,
`Самопробуждение: каждые 10 мин; задания по расписанию: каждые 5 мин`. Паролей и ключей в журнале нет.
Webhook: `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` (токен — из локального `.env`) — `url` на
`onrender.com`, `last_error_message` пустой. Адрес сервиса — начало поля `url` до `/tg/…` (владельцу присылать
его не нужно); `<адрес>/health` должен отвечать `ok`. Через сутки после первого деплоя: Render → **kpi-bot** → **Events** — записей
о засыпании (`spun down`) быть не должно (запрос бота к своему публичному адресу Render считает входящим).
Если они есть — подключить запасной будильник (п. 5). В журнале при сбое самопробуждения — строка
`Самопробуждение: публичный адрес бота не ответил (…)`.

**5. Запасной будильник (только если Render всё же усыпляет бота).** Любой внешний планировщик
(например, cron-job.org) каждые 5–10 минут: `https://<адрес>/health` — только будит;
`https://<адрес>/tick?key=<ключ>` — будит и сразу запускает задания. Ключ — `TICK_SECRET` из Render →
Environment или, если не задан, выведенный из токена:
`.venv\Scripts\python -c "from bot.config import get_settings; print(get_settings().tick_secret_value)"`.

**6. Временно вернуть бота на компьютер** (Render недоступен, переезд к другому провайдеру). Пока у бота
включён webhook, `run.bat` не запускается («Бот уже работает в облаке») — это защита от случайного запуска.
Порядок: остановить облачную копию (Render → **kpi-bot** → **Settings** → **Suspend Web Service**; работающая
копия каждые 5 минут возвращает webhook себе), затем в `.env` на компьютере — `TAKEOVER_WEBHOOK=1` (и, чтобы
работать с облачной базой, `DATABASE_URL` / `DATABASE_PASSWORD`), `run.bat`. Обратно на Render: остановить
бота на компьютере, убрать `TAKEOVER_WEBHOOK` из `.env`, Render → **Resume Web Service** — webhook бот поставит сам.

**7. Устойчивость к перезапускам.** Если Render остановит бота посреди AI-оценки сдачи (деплой, сбой), сдачу
в течение ~15 минут найдут задания по расписанию: оценка по правилам, руководителю — сдача, сотруднику — «передан
руководителю» (в журнале — `Оценка сдачи #… была прервана остановкой бота`). Ошибки подключения к базе при
старте пишутся одной строкой по-русски (пароль, адрес, Direct connection, приостановленный проект).

Как устроен режим webhook, самопробуждение и защита от двойного выполнения — [SPEC.md](../SPEC.md), §10.
