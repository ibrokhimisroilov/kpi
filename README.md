# Telegram-бот «Эффективность»: задачи и коэффициент эффективности сотрудников

Бот помогает начальнику ставить задачи сотрудникам, следить за сроками, принимать фактические
результаты и объективно считать **коэффициент эффективности (KPI)** каждого сотрудника за неделю,
месяц, квартал и год.

Главный принцип: оценивается не количество сообщений или часов работы, а **конечный результат**.
Каждая задача проходит один цикл:

**ПОРУЧЕНИЕ → ПЛАНОВЫЙ РЕЗУЛЬТАТ → СРОК → ФАКТИЧЕСКИЙ РЕЗУЛЬТАТ → ПРОВЕРКА → ОЦЕНКА → КОЭФФИЦИЕНТ ЭФФЕКТИВНОСТИ**

Всё работает **бесплатно**: бот запускается на вашем компьютере или на бесплатном сервере,
а AI — это бесплатные тарифы: Google Gemini и, по желанию, запасной Groq или Cloudflare (на случай,
если Gemini станет платным). Платных сервисов нет.

---

## Что умеет бот

1. **Начальник ставит задачу.** Выбирает сотрудника и указывает: задача → ожидаемый результат →
   срок → приоритет → вес задачи. Бот помогает сформулировать **измеримый** ожидаемый результат
   (например, «проверить 100 договоров и представить отчёт»), начальник его подтверждает.
2. **Сотрудник вносит устное поручение сам.** Начальник получает уведомление и подтверждает,
   исправляет или отклоняет его. Так все поручения оказываются в одной системе.
3. **Бот следит за сроками.** Напоминает о приближении срока, а когда срок истёк, спрашивает:
   «Что фактически сделано? Какой получен результат? Какие документы или материалы подтверждают выполнение?»
4. **Сотрудник сдаёт результат:** что сделано, какой результат, число (если в плане есть число),
   файлы и фото.
5. **AI сравнивает план и факт** и предлагает предварительную оценку, например «План: 100 договоров,
   факт: 110 → 110 %». AI только предлагает — **решение всегда за начальником**.
6. **Начальник проверяет:** ✅ подтвердить оценку, ✏️ изменить её или ↩ вернуть на доработку.
7. **Отчёты:** эффективность команды и каждого сотрудника, история оценок, выгрузка в Excel.
8. **Приложение в Telegram** (кнопка «Открыть» в чате, когда бот работает в облаке): то же самое с
   графиками, фильтрами, поиском и удобными формами — см. «Приложение в Telegram».

Все изменения задачи (кто, когда, что изменил) записываются в её историю.

## Что нужно (всё бесплатно)

- **Telegram** на телефоне или компьютере.
- **Компьютер с Windows 10/11**, который остаётся включённым и подключённым к интернету, —
  бот работает, пока он запущен. Вместо него можно взять бесплатный сервер (см. «Работа 24/7»).
- **Python 3.12** — бесплатная программа, нужна только для запуска на Windows: <https://www.python.org/downloads/>.
- **Ключ Google Gemini** — бесплатный, банковская карта не нужна. Без ключа бот тоже работает:
  подсказки и оценки считаются по простым правилам.
- По желанию — **запасной бесплатный ключ AI** (Groq или Cloudflare, тоже без карты): если Google
  закроет бесплатный тариф Gemini, бот сам продолжит работать через запасной (см. «Бесплатный AI»).

## Установка и запуск по шагам

### Шаг 1. Создайте бота у @BotFather и получите токен

1. В Telegram найдите **@BotFather** и нажмите «Запустить» (или отправьте `/start`).
2. Отправьте `/newbot`.
3. Введите название бота, например «KPI отдела».
4. Введите имя пользователя бота латиницей, оно должно заканчиваться на `bot`, например `kpi_otdela_bot`.
5. BotFather пришлёт **токен** — строку вида `1234567890:AAH...xyz`. Это пароль бота: никому его
   не показывайте и не пересылайте.

### Шаг 2. Получите бесплатный ключ Gemini

1. Откройте <https://aistudio.google.com/apikey> и войдите в свой Google-аккаунт.
2. Нажмите **Create API key** («Создать ключ») и скопируйте ключ (начинается с `AIza`).

Бесплатный тариф ограничивает число запросов в минуту и в день; небольшой команде этого хватает.
Если лимит закончился, бот сам переключится на другую модель, затем на запасной AI (если его ключ
задан), а затем на расчёт по правилам. Этот шаг можно пропустить — тогда бот работает без AI.

**По желанию — запасной AI (5 минут, без карты).** Откройте <https://console.groq.com/keys>, войдите
через Google или GitHub, нажмите **Create API Key** и впишите ключ (начинается с `gsk_`) в `.env`
строкой `GROQ_API_KEY=gsk_...`. Подробно — в [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md),
раздел «Запасной бесплатный AI».

### Шаг 3. Узнайте свой Telegram ID

Напишите в Telegram боту **@userinfobot**, он ответит сообщением с вашим `Id`, например `123456789`.
Этот номер нужен для `ADMIN_IDS`: люди из этого списка сразу становятся начальниками.
Если начальников несколько, перечислите их ID через запятую.

### Шаг 4. Заполните файл настроек `.env`

В папке бота есть образец `.env.example`. Скопируйте его под именем `.env`
(на Windows `run.bat` при первом запуске сделает это сам и откроет файл в Блокноте) и впишите три значения:

```
BOT_TOKEN=1234567890:AAH...xyz
ADMIN_IDS=123456789
GEMINI_API_KEY=AIza...
```

Пишите без кавычек и без пробелов вокруг `=`. Сохраните файл. Остальные настройки менять
не обязательно (см. «Настройки»).

> Файл `.env` содержит пароли — не отправляйте его никому и не выкладывайте в интернет.

### Шаг 5. Запустите бота

**На Windows:**

1. Установите Python 3.12 с <https://www.python.org/downloads/>. В первом окне установщика
   **обязательно отметьте галочку «Add python.exe to PATH»**.
2. Дважды щёлкните по файлу **`run.bat`** в папке бота.
   Первый запуск займёт несколько минут: создаётся папка `.venv` и скачиваются библиотеки.
3. Когда в окне появится строка `Бот @имя_бота подключён к Telegram`, бот работает.
4. **Не закрывайте это окно**: закрыли окно — бот остановился. Остановить бота можно так же,
   или нажав `Ctrl+C`.

**На сервере с Docker** (например, бесплатный сервер Oracle, см. ниже), в папке бота рядом с `.env`:

```
docker compose up -d          # запустить (бот сам поднимется после перезагрузки сервера)
docker compose logs -f        # посмотреть журнал работы (выход — Ctrl+C)
docker compose down           # остановить
docker compose up -d --build  # обновить после замены файлов бота
```

### Шаг 6. Проверьте

Откройте своего бота в Telegram (ссылка `t.me/имя_бота`) и нажмите **Запустить** (`/start`).
Если ваш ID указан в `ADMIN_IDS`, появится меню начальника.

## Как подключаются сотрудники

1. Отправьте сотрудникам ссылку на бота: `t.me/имя_бота`.
2. Сотрудник нажимает **Запустить**, вводит ФИО и должность — это заявка на доступ.
3. Начальникам приходит заявка с кнопками **✅ Подтвердить** / **❌ Отклонить**.
   Все заявки и сотрудники есть также в разделе **«👥 Сотрудники»**.
4. После подтверждения сотрудник получает своё меню и может работать.

Назначить сотрудника начальником, вернуть обычную роль, заблокировать или разблокировать доступ
можно в разделе «👥 Сотрудники».

## Голосовой ввод (по-узбекски и по-русски)

Печатать необязательно — боту можно говорить. Речь распознаёт тот же бесплатный Gemini (нужен
`GEMINI_API_KEY`); узбекская речь записывается латиницей, русская — кириллицей, можно вперемешку.

- **Ответить голосом на вопрос бота.** На любом шаге, где бот ждёт текст (название, ожидаемый результат,
  срок, «что сделано», комментарий к оценке, причина отмены), отправьте голосовое сообщение. Бот покажет
  «🎤 распознанный текст» и пойдёт дальше. Ошибку можно поправить в сводке: «✏️ Изменить».
- **Начальник: задача одним сообщением.** Просто отправьте боту голосовое (или нажмите «➕ Поставить
  задачу» и говорите): *«Алиеву до пятницы проверить 100 договоров и сдать отчёт»*. Бот сам найдёт
  сотрудника, составит название и измеримый результат, поставит срок и спросит только то, чего не хватает.
  Вес и приоритет выбираются кнопками, затем — сводка и «✅ Создать».
- **Сотрудник: голосовое без кнопки.** Бот спросит, что это: «➕ Новое поручение» или «✅ Результат по
  задаче». Поручение уйдёт начальнику на подтверждение; результат станет ответом «Что фактически сделано?»
  по выбранной задаче, дальше — обычная сдача (файлы, отправка).

- **В приложении** («Открыть» в чате с ботом) у текстовых полей есть кнопка «🎤»: нажмите, скажите, нажмите
  ещё раз — текст появится в поле. Вверху «Новой задачи» и «Поручения» — «🎤 Надиктовать задачу целиком».
  В первый раз телефон спросит разрешение на микрофон для Telegram — разрешите.

Запись — до 2 минут. Имя и должность при регистрации вводятся текстом, чтобы они не исказились. Если AI
временно недоступен, бот попросит написать текстом.

## Два языка: русский и узбекский

Каждый выбирает язык сам — **Русский** или **Oʻzbekcha** (латиница):

* при первом запуске бот сразу предлагает выбрать язык; если не выбирать — возьмёт язык Telegram;
* сменить язык в чате: кнопка меню **🌐 Til / Язык** или команда `/lang`;
* сменить язык в приложении: кнопка **🌐 Oʻzbekcha** / **🌐 Русский** справа от заголовка.

Язык один на чат и приложение. Переводится всё, что пишет бот: меню, вопросы, уведомления, напоминания,
приложение, Excel-отчёт. **Тексты задач, ФИО и комментарии не переводятся** — остаются так, как их написали.
Начальник с русским языком и сотрудник с узбекским работают над одной задачей: каждый получает сообщения
на своём языке. Срок можно писать по-узбекски: «ertaga», «juma kuni», «5-oktabr», «3 kundan keyin».

## Если начальник не успел ответить (автоподтверждение)

Чтобы работа не останавливалась, бот сам принимает решение, если начальник **не ответил за 24 часа**
(выходные считаются; ночью, с 21:00 до 08:00, бот ничего не подтверждает — переносит на 08:00):

- **Оценка результата.** Оценка, которую предложил AI, становится итоговой. Сотрудник получает результат,
  а начальник — сообщение «⏱ Оценка подтверждена автоматически» с кнопкой **«✏️ Изменить оценку»**:
  изменить её можно ещё **7 дней**.
- **Поручение сотрудника.** Принимается в работу с весом, который предложил AI (если AI недоступен — 10 %),
  и средним приоритетом. Вес, приоритет и срок начальник может поправить в карточке: «✏️ Изменить».
- **За 3 часа до этого** начальник получает напоминание — можно успеть проверить самому.

Всегда ждут начальника, сколько бы ни прошло времени:

- оценка **выше 100 %** (перевыполнение подтверждает человек);
- оценка, рассчитанная **без AI** (когда AI был недоступен, она строится на цифрах самого сотрудника);
- **заявки на доступ** к боту.

В каждом сообщении о новом результате или поручении бот пишет, когда оно подтвердится само, — или что
само не подтвердится и нужно решение. Срок и остальное меняются в настройках (`AUTO_CONFIRM_HOURS` и
соседние — см. «Настройки»); `AUTO_CONFIRM_HOURS=0` выключает автоподтверждение.

## Приложение в Telegram (мини-приложение)

Кроме кнопок в чате у бота есть **приложение внутри Telegram** — с графиками, списками, поиском и
обычными формами. Оно открывается прямо в Telegram (на телефоне и на компьютере), ничего
устанавливать не нужно, отдельного входа и пароля нет: Telegram сам сообщает приложению, кто его
открыл, а права те же, что в чате (начальник / сотрудник).

**Как открыть**

- кнопка **«Открыть»** слева от поля ввода сообщения в чате с ботом;
- или кнопка **«📱 Открыть приложение»** под приветствием после `/start`.

**Что в нём есть**

| Начальник | Сотрудник |
|---|---|
| 📊 **Команда** — KPI команды и каждого сотрудника за неделю, месяц, квартал, год, график по неделям, Excel-отчёт в чат | 📋 **Мои задачи** — задачи и сроки, кнопка «✅ Принять» |
| 📋 **Задачи** — все задачи с фильтрами (в работе, просрочены, на проверке…) и поиском по названию, сотруднику или номеру; карточка задачи с историей | 📤 **Сдать** — форма результата: что сделано, какой результат, число, файлы и фото с телефона |
| 📝 **Проверка** — результаты сотрудников с оценкой AI: подтвердить, изменить оценку или вернуть на доработку; поручения сотрудников — подтвердить или отклонить | 📈 **Мой KPI** — свой коэффициент, график по неделям, история оценок |
| ➕ **Новая** — форма задачи с кнопкой AI «✨ Сделать измеримым» и подсказкой загрузки сотрудника на неделю | ➕ **Поручение** — внести устное поручение начальника |

Приложение и чат — одно и то же: те же задачи, оценки и уведомления. Задачу можно поставить в
приложении, а принять в чате, сдать результат в приложении, а проверить в чате, — всё сходится.
Уведомления по-прежнему приходят в чат с ботом. Регистрация новых сотрудников и раздел
«👥 Сотрудники» (заявки, роли, блокировка) — только в чате.

**Что нужно настроить — ничего.** Приложение работает, когда бот запущен в облаке (Render,
`RUN_MODE=webhook`, см. «Работа 24/7 бесплатно»): бот сам раздаёт приложение со своего адреса
`https://<адрес бота>/app` и при каждом запуске сам ставит кнопку «Открыть» — у @BotFather ничего
настраивать не нужно. Это бесплатно: приложение работает на том же сервере и той же базе, что и бот.
Когда бот запущен на своём компьютере (`run.bat`, режим `polling`), приложения нет (Telegram открывает
приложения только по защищённому адресу https) — работает чат, как раньше. Выключить приложение:
`WEBAPP_ENABLED=0` (кнопки исчезнут после перезапуска бота).

## Как считается коэффициент эффективности (KPI)

У каждой задачи есть **вес** (важность, в процентах) и **оценка** (насколько выполнен результат, в процентах).
KPI — это средняя оценка с учётом весов:

**KPI = Σ (вес × оценка) ÷ Σ (вес)**

Пример из технического задания:

| Задача | Вес | Выполнение |
|---|---:|---:|
| Подготовка ТЗ | 30 % | 100 % |
| Анализ договоров | 20 % | 110 % |
| Отчёт | 20 % | 90 % |
| Работа с поставщиками | 30 % | 105 % |

(30×100 + 20×110 + 20×90 + 30×105) ÷ (30 + 20 + 20 + 30) = 10 150 ÷ 100 = 101,5 → **эффективность за неделю: 102 %**.

Веса не обязаны давать в сумме ровно 100 % — формула всё равно считает правильно.
При постановке задачи бот подсказывает, сколько веса уже набрано на этой неделе.

**Какие задачи входят в расчёт.** Задача относится к тому периоду, на который приходится её **срок**.

- ✅ **Выполненные** — с итоговой оценкой начальника.
- ⏰ **Просроченные и не сданные** — считаются как **0 %** (это можно отключить настройкой
  `OVERDUE_COUNTS_AS_ZERO=false`).
- Не входят, пока не решится их судьба: задачи **на проверке** (результат сдан, начальник ещё
  не оценил) и задачи **в работе**, срок которых ещё не наступил.
- Никогда не входят: отменённые задачи, отклонённые и ещё не подтверждённые поручения.

Месяц, квартал и год считаются по той же формуле по всем задачам периода (а не как среднее недель).

**Другие показатели в карточке сотрудника:** выполнено задач; просрочено (не сдано в срок или сдано
с опозданием); выполнение в срок (доля выполненных задач, сданных без опоздания); перевыполнено
(задачи с оценкой выше 100 %); внесено самостоятельно (поручения, которые сотрудник добавил сам);
в работе; на проверке.

**Как предлагается оценка.** AI сравнивает плановый и фактический результат, учитывает полноту,
сроки и приложенные документы и предлагает оценку от 0 до 150 % с коротким объяснением.
Если AI недоступен, оценка считается по правилу: факт ÷ план × 100 (или 100 %, если в плане нет числа)
минус 2 процентных пункта за каждый день опоздания, но не больше 20. Окончательную оценку
всегда ставит начальник.

## Напоминания

Бот проверяет сроки каждые 15 минут (в облаке, на Render, — каждые 5 минут) и пишет:

- **сотруднику — за 3 дня и за 1 день до срока**, а в день срока — **за 3 часа**
  (если подходят сразу несколько, приходит одно — ближайшее);
- **когда срок истёк** — сотруднику просьбу сдать результат с тремя вопросами
  («Что фактически сделано? Какой получен результат? Какие документы подтверждают выполнение?»),
  а начальнику — сообщение о просроченной задаче;
- **каждый день после 10:00** — сотруднику о задаче, которая всё ещё просрочена;
- **начальнику** — за 3 часа до того, как оценка или поручение подтвердятся автоматически
  (см. «Если начальник не успел ответить»);
- **начальнику** — если сданный результат ждёт проверки дольше 2 дней (раз в день): так бывает с оценками,
  которые сами не подтверждаются;
- **по понедельникам в 9:00** — всем начальникам сводку по команде за прошлую неделю.

С 21:00 до 08:00 («тихие часы») бот не беспокоит: напоминания придут утром.
Все сроки и время — в часовом поясе из настройки `TIMEZONE`.

## Бесплатный AI и что будет, если Gemini станет платным

AI нужен для двух вещей: превратить слова начальника в измеримый ожидаемый результат и сравнить
план с фактом (предложить оценку с объяснением). Бот спрашивает **бесплатных** AI-провайдеров по
очереди (`AI_PROVIDERS`) — только тех, чей ключ задан:

**Google Gemini → Groq → Cloudflare Workers AI → Mistral → OpenRouter → расчёт по правилам.**

- Закончился бесплатный лимит модели, Google закрыл бесплатный тариф («нужна оплата»), ключ перестал
  работать, сервис перегружен или не отвечает — бот **сам** переходит к следующей модели, затем к
  следующему провайдеру, а если не ответил никто — считает по правилам (с пометкой «Расчёт по правилам
  (AI недоступен)»). Ничего делать не нужно, бот не «ломается».
- Провайдера (или модель), который только что отказал из-за лимита или оплаты, бот какое-то время не
  спрашивает (после лимита — 10 минут или час, после «нужна оплата» / неверного ключа — 6 часов), чтобы
  не тратить время на заведомо закрытую дверь. После перезапуска бота всё пробуется заново.
- Сейчас (октябрь 2026) бесплатный тариф API Gemini **есть** и банковской карты не требует; Google лишь
  уменьшил бесплатные лимиты. Новости «Gemini стал платным» касаются бесплатного приложения-чата Gemini
  (по сообщениям прессы, его урезают с 9 октября 2026 года), а не ключа API, которым пользуется бот.
  Google может урезать и бесплатный API без предупреждения — запасной ключ на этот случай.
- Фото и PDF Gemini читает сам. Запасные провайдеры получают текст Word/Excel/txt, фото — только
  модели, которые их видят (`AI_VISION_MODELS`); содержимое PDF им не передаётся — AI знает, что файл
  приложен, и пишет в обосновании, что его стоит посмотреть начальнику.
- В журнале при запуске бот пишет цепочку, например:
  `AI: gemini (gemini-3.8-flash, …) → groq (openai/gpt-oss-120b, …) → расчёт по правилам`.

## Конфиденциальность

- Когда бот работает на вашем компьютере или сервере, все его данные хранятся **у вас**: в файле
  `data/bot.db`. Сами файлы-подтверждения остаются в Telegram, в базе хранятся только ссылки на них.
- **При работе в облаке** (Render + Supabase, см. «Работа 24/7 бесплатно») бот работает на серверах
  Render, а все данные — задачи, оценки, сотрудники — хранятся в базе Supabase (Франкфурт, Германия).
  Файлы-подтверждения и там остаются в Telegram.
- **Важно про бесплатный AI.** На бесплатном тарифе Gemini Google может использовать отправленные
  данные для улучшения своих продуктов, и их могут просматривать сотрудники Google. AI получает тексты
  задач и результатов, а при `AI_READ_FILES=true` — и содержимое приложенных файлов.
  - Запасные провайдеры: **Groq** и **Cloudflare** по своим правилам не обучают модели на отправленных
    данных (Groq может хранить запросы до 30 дней для проверки злоупотреблений); **Mistral** в бесплатном
    режиме может использовать данные для обучения (отключается в настройках аккаунта Mistral). Чтобы первым
    спрашивался Groq, укажите `AI_PROVIDERS=groq,gemini`.
  - **OpenRouter — осторожно.** Бесплатные модели OpenRouter обслуживают сторонние компании, и часть из них
    может хранить запросы или обучать на них свои модели. Модель `openrouter/free` (она есть в списке по
    умолчанию) выбирает исполнителя сама, поэтому заранее не известно, к кому попадут тексты задач, результаты
    и содержимое файлов сотрудников. Если вы задали `OPENROUTER_API_KEY`, откройте
    <https://openrouter.ai/settings/privacy> и **запретите** отправку запросов провайдерам, которые обучают
    модели на данных, — для бесплатных моделей там отдельный переключатель. После этого некоторые бесплатные
    модели могут стать недоступны — бот тогда сам перейдёт к следующей. Чтобы не рисковать вовсе, не задавайте
    `OPENROUTER_API_KEY` или уберите `openrouter/free` из `OPENROUTER_MODELS`.
  - Чтобы не отправлять AI содержимое файлов, укажите `AI_READ_FILES=false`:
    AI будет видеть только тексты и названия файлов.
  - Чтобы не отправлять ничего никуда, укажите `AI_PROVIDER=none`: AI выключится полностью,
    подсказки и оценки будут считаться по правилам.
- Ежедневная резервная копия базы (см. «Резервные копии») приходит начальникам в Telegram — значит,
  копия всех данных хранится и в их чатах. Не пересылайте этот файл посторонним. Чтобы копия не уходила
  в Telegram, укажите `BACKUP_ENABLED=false` и делайте копии вручную.
- Не отправляйте файл `.env` никому: в нём токен бота и ключи AI.

## Работа 24/7 бесплатно

Бот работает, пока запущен. Есть три бесплатных варианта.

| Вариант | Банковская карта | Что нужно делать потом | Инструкция |
|---|---|---|---|
| **Render + Supabase** (облако) — **рекомендуется** | не нужна | ничего: продлевать, заходить по расписанию и заводить «будильники» не нужно | **[docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)** |
| Свой компьютер, который не выключается | не нужна | следить, чтобы компьютер не выключался | ниже, «Вариант 1» |
| Сервер Oracle Cloud (Always Free) | нужна (только для проверки) | регулярно проверять, что Oracle не остановил сервер | [docs/DEPLOY.md](docs/DEPLOY.md) |

> Запускайте бота **только в одном месте**. Если один и тот же бот работает одновременно на компьютере
> и в облаке, Telegram будет отдавать сообщения то одному, то другому, а данные разойдутся. Поэтому,
> когда бот уже работает в облаке, `run.bat` на компьютере сам не запустится: покажет «Бот уже работает
> в облаке» — просто закройте окно.

### Вариант 1. Свой компьютер, который не выключается

1. Отключите спящий режим: **Параметры → Система → Питание → «Переводить в спящий режим» — «Никогда»**.
2. Добавьте бота в автозагрузку, чтобы он сам запускался после перезагрузки Windows:
   нажмите `Win+R`, введите `shell:startup`, нажмите Enter и в открывшуюся папку положите
   **ярлык** файла `run.bat`: правый щелчок по `run.bat` → «Создать ярлык» (в Windows 11 — сначала
   «Показать дополнительные параметры»), затем перетащите ярлык в эту папку.
3. Компьютер должен быть постоянно подключён к интернету. Если связь пропала, бот подождёт
   и продолжит работу сам.

### Вариант 2. Render + Supabase — без карты и без обслуживания (рекомендуется)

Бот работает на бесплатном хостинге **Render**, данные хранятся в бесплатной базе **Supabase**.
Бесплатный Render усыпляет сервер после 15 минут тишины, поэтому бот сам «будит» себя каждые
10 минут и каждые 5 минут сам проверяет напоминания, сводку и резервную копию — внешние «будильники»
не нужны. Банковская карта не нужна, продлевать ничего не нужно, заходить в панели по расписанию — тоже.
Обновления разработчик выкладывает в GitHub, Render ставит их сам.

От вас — один раз, около 30–40 минут: зарегистрироваться в GitHub, создать базу в Supabase (скопировать
пароль и строку подключения) и запустить бота в Render, вставив значения из файла `deploy\render.env`,
который заранее готовит разработчик. Код, перенос данных и выключение бота на компьютере — на разработчике.
Пошагово, с таблицей «если что-то не работает» — **[docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)**.

Технически бот на Render работает в режиме **webhook** (`RUN_MODE=webhook`): Telegram сам присылает
сообщения на адрес бота. На своём компьютере бот, как и раньше, работает в режиме `polling` — ничего
менять не нужно. Только на Render работает и **приложение в Telegram** (кнопка «Открыть» в чате) — бот
настраивает его сам при запуске.

### Вариант 3. Бесплатный сервер Oracle Cloud (Always Free)

Oracle даёт небольшой облачный сервер бесплатно навсегда (тариф **Always Free**): бот работает
круглосуточно, даже когда ваш компьютер выключен. От вас — регистрация (нужна карта Visa/Mastercard,
только для проверки) и создание сервера; установку и перенос бота делает разработчик двумя командами.
Все шаги, требования к карте, выбор региона и размер сервера — в **[docs/DEPLOY.md](docs/DEPLOY.md)**.

Учтите: Oracle может остановить бесплатную машину, если она долго почти не нагружена. Раз в неделю
проверяйте, что бот отвечает; если машина остановлена, запустите её в консоли Oracle — данные сохранятся.
Даже если машину удалят совсем, данные не пропадут: каждый вечер бот присылает начальникам копию базы
(см. «Резервные копии»).

## Резервные копии

Все данные — задачи, оценки, история, сотрудники — хранятся в базе данных. На своём компьютере и на
сервере с Docker это папка `data` (основной файл `bot.db`); в облаке (Render + Supabase) — база
PostgreSQL в Supabase.

**Копия каждый день — сама, в Telegram.** Каждый вечер в 23:00 (настройка `BACKUP_HOUR`) бот присылает
всем начальникам файл `kpi_backup_ГГГГ-ММ-ДД.db` — полную копию базы на этот момент. Сообщение приходит
без звука, останавливать бота не нужно. Файл остаётся в чате Telegram, даже если сервер с ботом пропадёт
(например, провайдер отключит или удалит бесплатную машину). Выключить: `BACKUP_ENABLED=false`.
Файл одинаковый для любой базы: и с компьютера, и из облака приходит один и тот же формат, и восстановить
его можно куда угодно — в папку `data` на компьютере или в базу Supabase.

**Как восстановить из файла на компьютере или сервере с Docker (папка `data`):**

1. Остановите бота (закройте окно `run.bat`; на сервере — `docker compose down`).
2. Скачайте из Telegram файл копии и положите его в папку `data` бота под именем **`bot.db`**
   (старый `bot.db` замените). Если в папке `data` есть файлы `bot.db-wal` и `bot.db-shm`, удалите их —
   они относятся к старой базе. На новом сервере просто создайте папку `data` и положите в неё файл.
3. Запустите бота. Все задачи, оценки и сотрудники вернутся в состояние на момент копии.

**Как восстановить облачную базу (Supabase) из файла.** Это делает разработчик — перешлите ему файл
копии из Telegram. Файл `.env` при этом **не меняется**: строка подключения и пароль берутся из
`deploy\render.env` только на время команды. На компьютере разработчика, в папке бота (есть папка `.venv`),
в PowerShell:

1. Остановить бота в облаке: Render → сервис → **Settings** → **Suspend Web Service**.
2. Загрузить копию в базу Supabase (путь к файлу — свой):
   ```
   Get-Content deploy\render.env | ForEach-Object { if ($_ -match '^(DATABASE_URL|DATABASE_PASSWORD)=(.+)$') { [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process') } }
   .venv\Scripts\python -m bot.tools.restore "$env:USERPROFILE\Downloads\kpi_backup_2026-10-02.db"
   Remove-Item Env:DATABASE_URL, Env:DATABASE_PASSWORD
   ```
   Команда создаст таблицы, если их нет, перенесёт все строки и напишет по-русски, сколько перенесено.
   Если в базе уже есть сотрудники, команда откажется, чтобы случайно не затереть рабочие данные;
   **заменить** содержимое базы копией (всё, что в ней сейчас, будет удалено) — с `--force` в конце.
   При любой ошибке (нет интернета, неверный пароль) база остаётся как была — исправьте и повторите.
3. Включить бота в облаке: Render → сервис → **Resume Web Service**.

Та же команда **переносит данные с компьютера в облако** при переезде на Render + Supabase: вместо файла
из Telegram указывается база бота с компьютера — `.venv\Scripts\python -m bot.tools.restore data\bot.db`
(бот на компьютере при этом должен быть остановлен; подробно — docs/DEPLOY_RENDER.md, «Для разработчика»,
п. 3). Номера задач и сотрудников сохраняются.

Telegram принимает от бота файлы до 50 МБ. Если копия вырастет больше 45 МБ, бот не сможет прислать
её файлом — он один раз предупредит об этом начальников, и копию нужно делать вручную.

**Копия вручную (папка `data`):** остановите бота, скопируйте папку `data` целиком (например, в
`data_2026-10-02`) и снова запустите бота. На сервере:

```
docker compose stop && cp -r data "data_$(date +%F)" && docker compose start
```

Восстановить такую копию: остановите бота, замените папку `data` сохранённой копией, запустите бота.

**Копия вручную (Supabase):** базу PostgreSQL копирует утилита `pg_dump` (её запускает разработчик:
`pg_dump "<строка подключения Session pooler>" > kpi_backup.sql`).

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| В окне: «Не задан BOT_TOKEN» или «BOT_TOKEN записан неверно» | откройте `.env` и вставьте токен от @BotFather целиком, без пробелов и кавычек |
| В окне: «Telegram не принял BOT_TOKEN» | токен устарел или с ошибкой: в @BotFather → `/mybots` → ваш бот → **API Token** возьмите актуальный |
| В окне: «Не найден Python 3.12» | установите Python 3.12 с python.org, отметив «Add python.exe to PATH» |
| Бот не отвечает | проверьте, что окно бота открыто (или `docker compose ps` на сервере) и компьютер не уснул |
| В журнале «Conflict: terminated by other getUpdates request» | бот запущен дважды — оставьте одну копию |
| В окне `run.bat`: «Бот уже работает в облаке» | всё в порядке: бот работает на Render, компьютер ему не нужен — закройте окно и уберите ярлык `run.bat` из автозагрузки |
| Закончился бесплатный лимит AI | ничего делать не нужно: бот сам перейдёт на следующую модель, затем на запасного провайдера (если задан его ключ), а если не ответил никто — посчитает оценку по правилам (с пометкой «Расчёт по правилам (AI недоступен)»). Лимиты восстанавливаются сами: поминутные — через минуту, дневные — на следующий день |
| Gemini стал платным / «нужна оплата» / ключ Gemini перестал работать | бот сам перейдёт на запасной AI, если задан `GROQ_API_KEY` (или ключ другого провайдера), иначе — на расчёт по правилам. Чтобы AI работал дальше, получите бесплатный ключ Groq (5 минут, без карты) — [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md), «Запасной бесплатный AI». **Карту и оплату не вводите** |
| AI не работает совсем (нет ключа, неверный ключ, сервис недоступен в вашей стране) | бот продолжает работать по правилам; в журнале при запуске видно, какие провайдеры подключены (строка «AI: …»). Проверьте ключи или отключите AI: `AI_PROVIDER=none` |
| Нет кнопки «Открыть» / «📱 Открыть приложение» | приложение есть, только когда бот работает в облаке (Render); на своём компьютере — только чат. На Render: проверьте, что нет строки `WEBAPP_ENABLED=0`; в журнале при запуске есть строка «Mini App: https://…/app». Кнопка меню обновляется при каждом запуске бота; если её не видно — закройте и снова откройте чат с ботом |
| Приложение пишет «Откройте приложение из Telegram» или «Сессия устарела» | откройте его кнопкой «Открыть» в чате с ботом (не по ссылке в браузере); если приложение было открыто больше суток — закройте и откройте снова |
| Приложение пишет «Вы ещё не зарегистрированы» или «Заявка на рассмотрении» | регистрация — только в чате: нажмите `/start` и заполните анкету, затем дождитесь подтверждения начальника |
| Сотруднику не приходят уведомления | сотрудник не нажал «Запустить» в боте или заблокировал бота — попросите открыть бота и нажать `/start` |
| Напоминания приходят не в то время | проверьте `TIMEZONE` в `.env` |
| Нужно больше подробностей о сбое | укажите `LOG_LEVEL=DEBUG`, перезапустите бота и посмотрите сообщения в окне (`docker compose logs -f` на сервере) |

## Для разработчиков

- Технический контракт проекта (модель данных, сигнатуры сервисов, сценарии, тексты) — **[SPEC.md](SPEC.md)**;
  исходное техническое задание — [docs/TZ.md](docs/TZ.md).
- Стек: Python 3.12, aiogram 3, SQLAlchemy 2 (async) + SQLite, APScheduler 3, google-genai
  (бесплатный тариф Gemini), httpx (запасные OpenAI-совместимые AI: Groq, Cloudflare, Mistral, OpenRouter),
  openpyxl, python-docx. Цепочка AI-провайдеров — `bot/ai/provider.py` (SPEC.md, §4).
- Запуск без `run.bat`: `python -m bot` (настройки — из `.env` или переменных окружения).
- Приложение в Telegram (Mini App): контракт — **[docs/MINIAPP_SPEC.md](docs/MINIAPP_SPEC.md)**, код —
  `bot/webapp/` (API на aiohttp в том же веб-сервере, что и webhook; SPA без сборки и сторонних
  библиотек — `bot/webapp/static/`). Вход — по подписанному Telegram `initData`, права — по базе.
  Локальная проверка в браузере без Telegram и без `.env`: `python -m bot.webapp.dev --seed-demo`, затем
  открыть `http://127.0.0.1:8081/dev/` и войти за начальника или сотрудника (временная база, фейковый
  Telegram, AI выключен). С `--real-telegram` (настоящий токен из `.env`) вход открывается только по
  ссылке с ключом запуска, которую сервер печатает в консоль (`/dev/?key=…`), и только за пользователей
  dev-базы: подпись с настоящим токеном принял бы и рабочий бот.
- Тесты: `pip install -r requirements-dev.txt`, затем `pytest`.
