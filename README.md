# Telegram-бот «Эффективность»: задачи и коэффициент эффективности сотрудников

Бот помогает руководителю ставить задачи сотрудникам, следить за сроками, принимать фактические
результаты и объективно считать **коэффициент эффективности (KPI)** каждого сотрудника за неделю,
месяц, квартал и год.

Главный принцип: оценивается не количество сообщений или часов работы, а **конечный результат**.
Каждая задача проходит один цикл:

**ПОРУЧЕНИЕ → ПЛАНОВЫЙ РЕЗУЛЬТАТ → СРОК → ФАКТИЧЕСКИЙ РЕЗУЛЬТАТ → ПРОВЕРКА → ОЦЕНКА → КОЭФФИЦИЕНТ ЭФФЕКТИВНОСТИ**

Всё работает **бесплатно**: бот запускается на вашем компьютере или на бесплатном сервере,
а AI — это бесплатный тариф Google Gemini. Платных сервисов нет.

---

## Что умеет бот

1. **Руководитель ставит задачу.** Выбирает сотрудника и указывает: задача → ожидаемый результат →
   срок → приоритет → вес задачи. Бот помогает сформулировать **измеримый** ожидаемый результат
   (например, «проверить 100 договоров и представить отчёт»), руководитель его подтверждает.
2. **Сотрудник вносит устное поручение сам.** Руководитель получает уведомление и подтверждает,
   исправляет или отклоняет его. Так все поручения оказываются в одной системе.
3. **Бот следит за сроками.** Напоминает о приближении срока, а когда срок истёк, спрашивает:
   «Что фактически сделано? Какой получен результат? Какие документы или материалы подтверждают выполнение?»
4. **Сотрудник сдаёт результат:** что сделано, какой результат, число (если в плане есть число),
   файлы и фото.
5. **AI сравнивает план и факт** и предлагает предварительную оценку, например «План: 100 договоров,
   факт: 110 → 110 %». AI только предлагает — **решение всегда за руководителем**.
6. **Руководитель проверяет:** ✅ подтвердить оценку, ✏️ изменить её или ↩ вернуть на доработку.
7. **Отчёты:** эффективность команды и каждого сотрудника, история оценок, выгрузка в Excel.

Все изменения задачи (кто, когда, что изменил) записываются в её историю.

## Что нужно (всё бесплатно)

- **Telegram** на телефоне или компьютере.
- **Компьютер с Windows 10/11**, который остаётся включённым и подключённым к интернету, —
  бот работает, пока он запущен. Вместо него можно взять бесплатный сервер (см. «Работа 24/7»).
- **Python 3.12** — бесплатная программа, нужна только для запуска на Windows: <https://www.python.org/downloads/>.
- **Ключ Google Gemini** — бесплатный, банковская карта не нужна. Без ключа бот тоже работает:
  подсказки и оценки считаются по простым правилам.

## Установка и запуск по шагам

### Шаг 1. Создайте бота у @BotFather и получите токен

1. В Telegram найдите **@BotFather** и нажмите «Запустить» (или отправьте `/start`).
2. Отправьте `/newbot`.
3. Введите название бота, например «KPI отдела».
4. Введите имя пользователя бота латиницей, оно должно заканчиваться на `bot`, например `kpi_otdela_bot`.
5. BotFather пришлёт **токен** — строку вида `1234567890:AAH...xyz`. Это пароль бота: никому его
   не показывайте и не пересылайте.

### Шаг 2. Получите бесплатный ключ Gemini

1. Откройте <https://aistudio.google.com/apikey> и войдите в свой Google-аккаунт.
2. Нажмите **Create API key** («Создать ключ») и скопируйте ключ (начинается с `AIza`).

Бесплатный тариф ограничивает число запросов в минуту и в день; небольшой команде этого хватает.
Если лимит закончился, бот сам переключится на другую модель, а затем на расчёт по правилам.
Этот шаг можно пропустить — тогда бот работает без AI.

### Шаг 3. Узнайте свой Telegram ID

Напишите в Telegram боту **@userinfobot**, он ответит сообщением с вашим `Id`, например `123456789`.
Этот номер нужен для `ADMIN_IDS`: люди из этого списка сразу становятся руководителями.
Если руководителей несколько, перечислите их ID через запятую.

### Шаг 4. Заполните файл настроек `.env`

В папке бота есть образец `.env.example`. Скопируйте его под именем `.env`
(на Windows `run.bat` при первом запуске сделает это сам и откроет файл в Блокноте) и впишите три значения:

```
BOT_TOKEN=1234567890:AAH...xyz
ADMIN_IDS=123456789
GEMINI_API_KEY=AIza...
```

Пишите без кавычек и без пробелов вокруг `=`. Сохраните файл. Остальные настройки менять
не обязательно (см. «Настройки»).

> Файл `.env` содержит пароли — не отправляйте его никому и не выкладывайте в интернет.

### Шаг 5. Запустите бота

**На Windows:**

1. Установите Python 3.12 с <https://www.python.org/downloads/>. В первом окне установщика
   **обязательно отметьте галочку «Add python.exe to PATH»**.
2. Дважды щёлкните по файлу **`run.bat`** в папке бота.
   Первый запуск займёт несколько минут: создаётся папка `.venv` и скачиваются библиотеки.
3. Когда в окне появится строка `Бот @имя_бота подключён к Telegram`, бот работает.
4. **Не закрывайте это окно**: закрыли окно — бот остановился. Остановить бота можно так же,
   или нажав `Ctrl+C`.

**На сервере с Docker** (например, бесплатный сервер Oracle, см. ниже), в папке бота рядом с `.env`:

```
docker compose up -d          # запустить (бот сам поднимется после перезагрузки сервера)
docker compose logs -f        # посмотреть журнал работы (выход — Ctrl+C)
docker compose down           # остановить
docker compose up -d --build  # обновить после замены файлов бота
```

### Шаг 6. Проверьте

Откройте своего бота в Telegram (ссылка `t.me/имя_бота`) и нажмите **Запустить** (`/start`).
Если ваш ID указан в `ADMIN_IDS`, появится меню руководителя.

## Как подключаются сотрудники

1. Отправьте сотрудникам ссылку на бота: `t.me/имя_бота`.
2. Сотрудник нажимает **Запустить**, вводит ФИО и должность — это заявка на доступ.
3. Руководителям приходит заявка с кнопками **✅ Подтвердить** / **❌ Отклонить**.
   Все заявки и сотрудники есть также в разделе **«👥 Сотрудники»**.
4. После подтверждения сотрудник получает своё меню и может работать.

Назначить сотрудника руководителем, вернуть обычную роль, заблокировать или разблокировать доступ
можно в разделе «👥 Сотрудники».

## Как считается коэффициент эффективности (KPI)

У каждой задачи есть **вес** (важность, в процентах) и **оценка** (насколько выполнен результат, в процентах).
KPI — это средняя оценка с учётом весов:

**KPI = Σ (вес × оценка) ÷ Σ (вес)**

Пример из технического задания:

| Задача | Вес | Выполнение |
|---|---:|---:|
| Подготовка ТЗ | 30 % | 100 % |
| Анализ договоров | 20 % | 110 % |
| Отчёт | 20 % | 90 % |
| Работа с поставщиками | 30 % | 105 % |

(30×100 + 20×110 + 20×90 + 30×105) ÷ (30 + 20 + 20 + 30) = 10 150 ÷ 100 = 101,5 → **эффективность за неделю: 102 %**.

Веса не обязаны давать в сумме ровно 100 % — формула всё равно считает правильно.
При постановке задачи бот подсказывает, сколько веса уже набрано на этой неделе.

**Какие задачи входят в расчёт.** Задача относится к тому периоду, на который приходится её **срок**.

- ✅ **Выполненные** — с итоговой оценкой руководителя.
- ⏰ **Просроченные и не сданные** — считаются как **0 %** (это можно отключить настройкой
  `OVERDUE_COUNTS_AS_ZERO=false`).
- Не входят, пока не решится их судьба: задачи **на проверке** (результат сдан, руководитель ещё
  не оценил) и задачи **в работе**, срок которых ещё не наступил.
- Никогда не входят: отменённые задачи, отклонённые и ещё не подтверждённые поручения.

Месяц, квартал и год считаются по той же формуле по всем задачам периода (а не как среднее недель).

**Другие показатели в карточке сотрудника:** выполнено задач; просрочено (не сдано в срок или сдано
с опозданием); выполнение в срок (доля выполненных задач, сданных без опоздания); перевыполнено
(задачи с оценкой выше 100 %); внесено самостоятельно (поручения, которые сотрудник добавил сам);
в работе; на проверке.

**Как предлагается оценка.** AI сравнивает плановый и фактический результат, учитывает полноту,
сроки и приложенные документы и предлагает оценку от 0 до 150 % с коротким объяснением.
Если AI недоступен, оценка считается по правилу: факт ÷ план × 100 (или 100 %, если в плане нет числа)
минус 2 процентных пункта за каждый день опоздания, но не больше 20. Окончательную оценку
всегда ставит руководитель.

## Напоминания

Бот проверяет сроки каждые 15 минут (в облаке, на Render, — каждые 5 минут) и пишет:

- **сотруднику — за 3 дня и за 1 день до срока**, а в день срока — **за 3 часа**
  (если подходят сразу несколько, приходит одно — ближайшее);
- **когда срок истёк** — сотруднику просьбу сдать результат с тремя вопросами
  («Что фактически сделано? Какой получен результат? Какие документы подтверждают выполнение?»),
  а руководителю — сообщение о просроченной задаче;
- **каждый день после 10:00** — сотруднику о задаче, которая всё ещё просрочена;
- **руководителю** — если сданный результат ждёт проверки дольше 2 дней (раз в день);
- **по понедельникам в 9:00** — всем руководителям сводку по команде за прошлую неделю.

С 21:00 до 08:00 («тихие часы») бот не беспокоит: напоминания придут утром.
Все сроки и время — в часовом поясе из настройки `TIMEZONE`.

## Настройки

Настройки хранятся в файле `.env`. Обязательны только первые три строки, остальные можно не трогать.
Чтобы изменить настройку, уберите `#` в начале её строки в `.env`, впишите значение
и перезапустите бота.

| Параметр | По умолчанию | Что означает |
|---|---|---|
| `BOT_TOKEN` | — (обязательно) | токен бота от @BotFather |
| `ADMIN_IDS` | пусто | Telegram ID руководителей через запятую; они сразу получают права руководителя |
| `GEMINI_API_KEY` | пусто | бесплатный ключ Google Gemini; пусто — AI выключен, всё по правилам |
| `DATABASE_URL` | `sqlite+aiosqlite:///data/bot.db` | где хранится база данных: по умолчанию файл `data/bot.db`; в облаке — PostgreSQL, например строка Supabase «Session pooler» `postgresql://postgres.<проект>:<пароль>@aws-0-eu-central-1.pooler.supabase.com:5432/postgres` (см. [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)) |
| `DATABASE_PASSWORD` | пусто | пароль базы PostgreSQL отдельно от адреса: строку Supabase можно вставить в `DATABASE_URL` как есть, с `[YOUR-PASSWORD]`, — бот подставит пароль сам (спецсимволы экранировать не нужно); пароль, вписанный прямо в `DATABASE_URL`, важнее |
| `TIMEZONE` | `Asia/Tashkent` | часовой пояс для сроков и напоминаний |
| `AI_PROVIDER` | `gemini` | `gemini` — работать с AI; `none` — AI полностью выключен |
| `GEMINI_MODELS` | `gemini-3.8-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite` | модели Gemini по порядку: закончился лимит у первой — берётся следующая |
| `AI_TIMEOUT_SEC` | `60` | сколько секунд ждать ответа AI |
| `AI_READ_FILES` | `true` | передавать ли AI содержимое приложенных файлов (PDF, фото, Word, Excel, текст) |
| `AI_MAX_FILE_MB` | `10` | файлы больше этого размера (МБ) AI не читает |
| `MAX_SCORE` | `150` | максимальная оценка задачи, % |
| `LATE_PENALTY_PER_DAY` | `2.0` | рекомендуемый штраф за день опоздания, процентных пунктов |
| `LATE_PENALTY_MAX` | `20.0` | максимальный штраф за опоздание, процентных пунктов |
| `OVERDUE_COUNTS_AS_ZERO` | `true` | просроченная несданная задача входит в KPI как 0 % |
| `DEFAULT_DEADLINE_TIME` | `18:00` | время срока, если указана только дата |
| `REMINDER_DAYS_BEFORE` | `3,1` | за сколько дней до срока напоминать |
| `REMINDER_HOURS_BEFORE` | `3` | за сколько часов до срока напомнить в день срока |
| `OVERDUE_REMINDER_HOUR` | `10` | с какого часа каждый день напоминать о просроченных задачах |
| `QUIET_HOURS_START` | `21` | начало «тихих часов» (бот не пишет) |
| `QUIET_HOURS_END` | `8` | конец «тихих часов» |
| `DIGEST_WEEKDAY` | `0` | день еженедельной сводки: 0 — понедельник … 6 — воскресенье |
| `DIGEST_HOUR` | `9` | час еженедельной сводки |
| `REVIEW_REMINDER_DAYS` | `2` | через сколько дней напомнить руководителю о непроверенном результате |
| `SCHEDULER_INTERVAL_MIN` | `15` | как часто (в минутах) бот проверяет, пора ли напомнить; действует только при запуске на компьютере или сервере (`RUN_MODE=polling`) — в облаке (`webhook`) бот проверяет каждые 5 минут |
| `BACKUP_ENABLED` | `true` | каждый день присылать руководителям файл с копией базы (см. «Резервные копии»); `false` — не присылать |
| `BACKUP_HOUR` | `23` | в котором часу (0–23, по `TIMEZONE`) присылать копию базы |
| `LOG_LEVEL` | `INFO` | подробность журнала работы: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `RUN_MODE` | `polling` | как бот получает сообщения: `polling` — сам забирает их у Telegram (свой компьютер, сервер с Docker); `webhook` — Telegram присылает их на веб-адрес бота (Render, см. [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)) |
| `PUBLIC_URL` | пусто | публичный адрес бота для `webhook`, например `https://kpi-bot.onrender.com`; на Render не нужен — адрес берётся из `RENDER_EXTERNAL_URL`, которую Render задаёт сам |
| `PORT` | `8080` | порт веб-сервера в режиме `webhook`; на Render не нужен — Render задаёт его сам |
| `WEBHOOK_SECRET` | выводится из `BOT_TOKEN` | секрет адреса, на который Telegram присылает сообщения (латинские буквы и цифры); обычно задавать не нужно |
| `TAKEOVER_WEBHOOK` | `false` | если бот уже работает в облаке (у него включён webhook), запуск на компьютере останавливается с объяснением — чтобы случайно не увести бота из облака. `TAKEOVER_WEBHOOK=1` — всё-таки перенести бота на этот компьютер; облачную копию перед этим нужно остановить (см. [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)) |
| `TICK_SECRET` | выводится из `BOT_TOKEN` | ключ адреса `https://<адрес бота>/tick?key=<ключ>` — только для необязательного внешнего резервного планировщика: в режиме `webhook` бот сам запускает напоминания и сам не даёт Render себя усыпить, обычно задавать не нужно; меняется вместе с токеном бота, если не задан явно |

## Конфиденциальность

- Когда бот работает на вашем компьютере или сервере, все его данные хранятся **у вас**: в файле
  `data/bot.db`. Сами файлы-подтверждения остаются в Telegram, в базе хранятся только ссылки на них.
- **При работе в облаке** (Render + Supabase, см. «Работа 24/7 бесплатно») бот работает на серверах
  Render, а все данные — задачи, оценки, сотрудники — хранятся в базе Supabase (Франкфурт, Германия).
  Файлы-подтверждения и там остаются в Telegram.
- **Важно про бесплатный AI.** На бесплатном тарифе Gemini Google может использовать отправленные
  данные для улучшения своих продуктов, и их могут просматривать сотрудники Google. AI получает тексты
  задач и результатов, а при `AI_READ_FILES=true` — и содержимое приложенных файлов.
  - Чтобы не отправлять в Google содержимое файлов, укажите `AI_READ_FILES=false`:
    AI будет видеть только тексты и названия файлов.
  - Чтобы не отправлять в Google ничего, укажите `AI_PROVIDER=none`: AI выключится полностью,
    подсказки и оценки будут считаться по правилам.
- Ежедневная резервная копия базы (см. «Резервные копии») приходит руководителям в Telegram — значит,
  копия всех данных хранится и в их чатах. Не пересылайте этот файл посторонним. Чтобы копия не уходила
  в Telegram, укажите `BACKUP_ENABLED=false` и делайте копии вручную.
- Не отправляйте файл `.env` никому: в нём токен бота и ключ Gemini.

## Работа 24/7 бесплатно

Бот работает, пока запущен. Есть три бесплатных варианта.

| Вариант | Банковская карта | Что нужно делать потом | Инструкция |
|---|---|---|---|
| **Render + Supabase** (облако) — **рекомендуется** | не нужна | ничего: продлевать, заходить по расписанию и заводить «будильники» не нужно | **[docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)** |
| Свой компьютер, который не выключается | не нужна | следить, чтобы компьютер не выключался | ниже, «Вариант 1» |
| Сервер Oracle Cloud (Always Free) | нужна (только для проверки) | регулярно проверять, что Oracle не остановил сервер | [docs/DEPLOY.md](docs/DEPLOY.md) |

> Запускайте бота **только в одном месте**. Если один и тот же бот работает одновременно на компьютере
> и в облаке, Telegram будет отдавать сообщения то одному, то другому, а данные разойдутся. Поэтому,
> когда бот уже работает в облаке, `run.bat` на компьютере сам не запустится: покажет «Бот уже работает
> в облаке» — просто закройте окно.

### Вариант 1. Свой компьютер, который не выключается

1. Отключите спящий режим: **Параметры → Система → Питание → «Переводить в спящий режим» — «Никогда»**.
2. Добавьте бота в автозагрузку, чтобы он сам запускался после перезагрузки Windows:
   нажмите `Win+R`, введите `shell:startup`, нажмите Enter и в открывшуюся папку положите
   **ярлык** файла `run.bat`: правый щелчок по `run.bat` → «Создать ярлык» (в Windows 11 — сначала
   «Показать дополнительные параметры»), затем перетащите ярлык в эту папку.
3. Компьютер должен быть постоянно подключён к интернету. Если связь пропала, бот подождёт
   и продолжит работу сам.

### Вариант 2. Render + Supabase — без карты и без обслуживания (рекомендуется)

Бот работает на бесплатном хостинге **Render**, данные хранятся в бесплатной базе **Supabase**.
Бесплатный Render усыпляет сервер после 15 минут тишины, поэтому бот сам «будит» себя каждые
10 минут и каждые 5 минут сам проверяет напоминания, сводку и резервную копию — внешние «будильники»
не нужны. Банковская карта не нужна, продлевать ничего не нужно, заходить в панели по расписанию — тоже.
Обновления разработчик выкладывает в GitHub, Render ставит их сам.

От вас — один раз, около 30–40 минут: зарегистрироваться в GitHub, создать базу в Supabase (скопировать
пароль и строку подключения) и запустить бота в Render, вставив значения из файла `deploy\render.env`,
который заранее готовит разработчик. Код, перенос данных и выключение бота на компьютере — на разработчике.
Пошагово, с таблицей «если что-то не работает» — **[docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)**.

Технически бот на Render работает в режиме **webhook** (`RUN_MODE=webhook`): Telegram сам присылает
сообщения на адрес бота. На своём компьютере бот, как и раньше, работает в режиме `polling` — ничего
менять не нужно.

### Вариант 3. Бесплатный сервер Oracle Cloud (Always Free)

Oracle даёт небольшой облачный сервер бесплатно навсегда (тариф **Always Free**): бот работает
круглосуточно, даже когда ваш компьютер выключен. От вас — регистрация (нужна карта Visa/Mastercard,
только для проверки) и создание сервера; установку и перенос бота делает разработчик двумя командами.
Все шаги, требования к карте, выбор региона и размер сервера — в **[docs/DEPLOY.md](docs/DEPLOY.md)**.

Учтите: Oracle может остановить бесплатную машину, если она долго почти не нагружена. Раз в неделю
проверяйте, что бот отвечает; если машина остановлена, запустите её в консоли Oracle — данные сохранятся.
Даже если машину удалят совсем, данные не пропадут: каждый вечер бот присылает руководителям копию базы
(см. «Резервные копии»).

## Резервные копии

Все данные — задачи, оценки, история, сотрудники — хранятся в базе данных. На своём компьютере и на
сервере с Docker это папка `data` (основной файл `bot.db`); в облаке (Render + Supabase) — база
PostgreSQL в Supabase.

**Копия каждый день — сама, в Telegram.** Каждый вечер в 23:00 (настройка `BACKUP_HOUR`) бот присылает
всем руководителям файл `kpi_backup_ГГГГ-ММ-ДД.db` — полную копию базы на этот момент. Сообщение приходит
без звука, останавливать бота не нужно. Файл остаётся в чате Telegram, даже если сервер с ботом пропадёт
(например, провайдер отключит или удалит бесплатную машину). Выключить: `BACKUP_ENABLED=false`.
Файл одинаковый для любой базы: и с компьютера, и из облака приходит один и тот же формат, и восстановить
его можно куда угодно — в папку `data` на компьютере или в базу Supabase.

**Как восстановить из файла на компьютере или сервере с Docker (папка `data`):**

1. Остановите бота (закройте окно `run.bat`; на сервере — `docker compose down`).
2. Скачайте из Telegram файл копии и положите его в папку `data` бота под именем **`bot.db`**
   (старый `bot.db` замените). Если в папке `data` есть файлы `bot.db-wal` и `bot.db-shm`, удалите их —
   они относятся к старой базе. На новом сервере просто создайте папку `data` и положите в неё файл.
3. Запустите бота. Все задачи, оценки и сотрудники вернутся в состояние на момент копии.

**Как восстановить облачную базу (Supabase) из файла.** Это делает разработчик — перешлите ему файл
копии из Telegram. Файл `.env` при этом **не меняется**: строка подключения и пароль берутся из
`deploy\render.env` только на время команды. На компьютере разработчика, в папке бота (есть папка `.venv`),
в PowerShell:

1. Остановить бота в облаке: Render → сервис → **Settings** → **Suspend Web Service**.
2. Загрузить копию в базу Supabase (путь к файлу — свой):
   ```
   Get-Content deploy\render.env | ForEach-Object { if ($_ -match '^(DATABASE_URL|DATABASE_PASSWORD)=(.+)$') { [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process') } }
   .venv\Scripts\python -m bot.tools.restore "$env:USERPROFILE\Downloads\kpi_backup_2026-10-02.db"
   Remove-Item Env:DATABASE_URL, Env:DATABASE_PASSWORD
   ```
   Команда создаст таблицы, если их нет, перенесёт все строки и напишет по-русски, сколько перенесено.
   Если в базе уже есть сотрудники, команда откажется, чтобы случайно не затереть рабочие данные;
   **заменить** содержимое базы копией (всё, что в ней сейчас, будет удалено) — с `--force` в конце.
   При любой ошибке (нет интернета, неверный пароль) база остаётся как была — исправьте и повторите.
3. Включить бота в облаке: Render → сервис → **Resume Web Service**.

Та же команда **переносит данные с компьютера в облако** при переезде на Render + Supabase: вместо файла
из Telegram указывается база бота с компьютера — `.venv\Scripts\python -m bot.tools.restore data\bot.db`
(бот на компьютере при этом должен быть остановлен; подробно — docs/DEPLOY_RENDER.md, «Для разработчика»,
п. 3). Номера задач и сотрудников сохраняются.

Telegram принимает от бота файлы до 50 МБ. Если копия вырастет больше 45 МБ, бот не сможет прислать
её файлом — он один раз предупредит об этом руководителей, и копию нужно делать вручную.

**Копия вручную (папка `data`):** остановите бота, скопируйте папку `data` целиком (например, в
`data_2026-10-02`) и снова запустите бота. На сервере:

```
docker compose stop && cp -r data "data_$(date +%F)" && docker compose start
```

Восстановить такую копию: остановите бота, замените папку `data` сохранённой копией, запустите бота.

**Копия вручную (Supabase):** базу PostgreSQL копирует утилита `pg_dump` (её запускает разработчик:
`pg_dump "<строка подключения Session pooler>" > kpi_backup.sql`).

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| В окне: «Не задан BOT_TOKEN» или «BOT_TOKEN записан неверно» | откройте `.env` и вставьте токен от @BotFather целиком, без пробелов и кавычек |
| В окне: «Telegram не принял BOT_TOKEN» | токен устарел или с ошибкой: в @BotFather → `/mybots` → ваш бот → **API Token** возьмите актуальный |
| В окне: «Не найден Python 3.12» | установите Python 3.12 с python.org, отметив «Add python.exe to PATH» |
| Бот не отвечает | проверьте, что окно бота открыто (или `docker compose ps` на сервере) и компьютер не уснул |
| В журнале «Conflict: terminated by other getUpdates request» | бот запущен дважды — оставьте одну копию |
| В окне `run.bat`: «Бот уже работает в облаке» | всё в порядке: бот работает на Render, компьютер ему не нужен — закройте окно и уберите ярлык `run.bat` из автозагрузки |
| Закончился бесплатный лимит AI | ничего делать не нужно: бот сам перейдёт на следующую модель из `GEMINI_MODELS`, а если лимит исчерпан у всех — посчитает оценку по правилам (с пометкой «Расчёт по правилам (AI недоступен)»). Лимиты восстанавливаются сами: поминутные — через минуту, дневные — на следующий день |
| AI не работает совсем (нет ключа, неверный ключ, сервис недоступен в вашей стране) | бот продолжает работать по правилам; проверьте `GEMINI_API_KEY` или отключите AI: `AI_PROVIDER=none` |
| Сотруднику не приходят уведомления | сотрудник не нажал «Запустить» в боте или заблокировал бота — попросите открыть бота и нажать `/start` |
| Напоминания приходят не в то время | проверьте `TIMEZONE` в `.env` |
| Нужно больше подробностей о сбое | укажите `LOG_LEVEL=DEBUG`, перезапустите бота и посмотрите сообщения в окне (`docker compose logs -f` на сервере) |
